# Mac Fleet Usage

This folder keeps the local Mac setup for using `ccusage` across multiple Macs.
It is intentionally separate from the product code.

## Model

Each Mac exports its local Codex logs into a shared fleet folder:

```text
$CCUSAGE_FLEET_ROOT/
  codex/
    mac-mini-m4-1/
      sessions/
      archived_sessions/
      config.toml
    macbook-air-m4/
      sessions/
      archived_sessions/
      config.toml
```

`ccusage` already accepts comma-separated `CODEX_HOME` directories, so combined
reports are generated by pointing it at every per-Mac folder. Individual reports
are generated by pointing it at one per-Mac folder.

By default, the scripts export to this local folder:

```sh
$HOME/Library/Application Support/ccusage-fleet
```

That is safe for a single Mac but does not sync across machines. To combine
multiple Macs, explicitly choose a shared `CCUSAGE_FLEET_ROOT`, such as iCloud
Drive, Syncthing, a NAS folder, or an SSH/rsync destination. Do not put exported
Codex logs in git.

Codex logs can contain sensitive prompt, path, and code context. Treat the fleet
folder as private data.

## Install On Each Mac

Clone your fork and install the CLI:

```sh
git clone git@github.com:nibrwr/ccusage.git ~/Development/ccusage
cd ~/Development/ccusage
ops/macos/install-ccusage.zsh
```

If the install script reports `cargo was not found`, install Rust first:

```sh
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
exec zsh
ops/macos/install-ccusage.zsh
```

Pick the machine config for that Mac:

```sh
source ops/macos/machines/mac-mini-m4-1.env
# or:
source ops/macos/machines/macbook-air-m4.env
```

Machine configs also enable local refresh before report commands. Pass
`--no-refresh` to a report command when you only want to read the already
exported fleet data.

Optionally opt into iCloud Drive as the shared fleet folder:

```sh
source ops/macos/fleet-roots/icloud.env
```

Export that Mac's Codex logs:

```sh
ops/macos/export-codex-logs.zsh
```

If you previously exported to the local default
`~/Library/Application Support/ccusage-fleet`, source your shared fleet root
profile and rerun the export so the logs land in the shared folder.

## Reports

Combined usage across every exported Mac:

```sh
ops/macos/report-codex-fleet.zsh monthly
ops/macos/report-codex-fleet.zsh daily
ops/macos/report-codex-fleet.zsh session
```

Usage broken out by Mac:

```sh
ops/macos/report-codex-fleet-by-machine.zsh monthly
ops/macos/report-codex-fleet-by-machine.zsh weekly
ops/macos/report-codex-fleet-by-machine.zsh daily --since 2026-05-01
```

Individual Mac usage:

```sh
ops/macos/report-codex-fleet.zsh --machine mac-mini-m4-1 monthly
ops/macos/report-codex-fleet.zsh --machine macbook-air-m4 monthly
```

Pass normal `ccusage codex` options after the report name:

```sh
ops/macos/report-codex-fleet.zsh monthly --json
ops/macos/report-codex-fleet.zsh --machine mac-mini-m4-1 daily --since 2026-05-01
```

## Scheduled Export

After sourcing the correct machine config, install a launchd job:

```sh
ops/macos/install-export-launchd.zsh
```

The job runs every 15 minutes by default. Override the interval with
`CCUSAGE_EXPORT_INTERVAL_SECONDS`.

For fresher shared reports, use a shorter interval when installing the job:

```sh
CCUSAGE_EXPORT_INTERVAL_SECONDS=60 ops/macos/install-export-launchd.zsh
```

Check whether the job is loaded and when each Mac last exported data:

```sh
ops/macos/status-codex-fleet.zsh
```

## Scheduled Reports

Install weekly and monthly by-machine report delivery from the reporting Mac's
GUI session:

```sh
source ops/macos/fleet-roots/icloud.env
ops/macos/install-report-launchd.zsh
```

Reports are saved under `$CCUSAGE_FLEET_ROOT/reports` and a macOS notification
is posted when each report is generated. By default, weekly reports run Monday
at 08:00 and monthly reports run on day 1 at 08:00.

Generate a report immediately:

```sh
ops/macos/generate-codex-fleet-report.zsh weekly
ops/macos/generate-codex-fleet-report.zsh monthly
```

## Sanitized Codex metadata mode

For the Continuous Improvement System, use `--metadata` on the existing
installer labels. This mode requires the existing iCloud fleet root, a local
Python 3.9+ interpreter and an installed ccusage with JSON session,
`--offline`, `--no-cost` and `--single-thread` support. The verified M6
ccusage executable was 20.0.49. Validate the installed CLI separately on
each host. The collector combines native and ccusage evidence conservatively.
Activity without corroborated counters remains partial or unlinked. It
never emits session paths, config files or transcript content.

Place the reviewed Python files in a stable owner-only support directory.
Use the applicable verified machine profile before installation. After matching
the physical Mac to its fleet ID, set `CCUSAGE_VERIFIED_HOSTNAME` to the
verified local name from `scutil --get LocalHostName`. The local
M6 machine ID is `mac-mini-m6`; the two existing IDs are unchanged.

```sh
source ops/macos/fleet-roots/icloud.env
export CCUSAGE_MACHINE_ID=mac-mini-m6
export CCUSAGE_VERIFIED_HOSTNAME=verified-local-hostname
export CCUSAGE_METADATA_PYTHON=/absolute/path/to/python3
export CCUSAGE_BINARY="$HOME/.local/bin/ccusage"
ops/macos/install-export-launchd.zsh --metadata --render | plutil -lint -
ops/macos/install-export-launchd.zsh --metadata
```

The same named exporter runs once when loaded, then every 900 seconds on
the minis or 3,600 seconds on the Air. It has no keep-awake or KeepAlive
option. Successful collection atomically replaces
`summaries/<machine>/latest.json`. An optional `--session <UUID>` targeted
proof is a separate file. The existing raw-log and report commands remain
available for their prior authorized installations. Keep their historical
files and do not point the raw exporter at them during this rollout.

For an approved M4 or Air migration, first verify a complete sanitized summary
from that Mac and qualify any replacement for reports that still use the raw
exports. Run the same metadata installer with `--migrate-legacy-export`. It
matches the original label, loaded arguments, ownership and fleet paths, then
moves the original plist and saves the verified summary under the private
ccusage logs directory. If the candidate fails, the installer unloads it and
preserves the last verified summary. The raw exporter plist stays parked.
After a failure or interruption, use the exact same command and package to
resume, finish unloading the original job if necessary, and verify a new
summary from the replacement.

The M6 report uses Orchestrator's deterministic analyzer. Before installing,
verify schedule capacity and preserve any intentional disablement. Pass the
reviewed analyzer and optional owner-only evidence files via
`CCUSAGE_IMPROVEMENT_SCRIPT`, `CCUSAGE_IMPROVEMENT_PRS` and
`CCUSAGE_IMPROVEMENT_BINDINGS` as absolute paths. The metadata reporter
installer renders or qualifies only the existing weekly label.

```sh
ops/macos/install-report-launchd.zsh --metadata --render | plutil -lint -
# After confirming current owner, disablement, capacity and time zone:
ops/macos/install-report-launchd.zsh --metadata --schedule-qualified
```

Read back the exact label in the owner's `gui/<uid>` domain and observe its
last exit, interval or calendar configuration and output freshness. A
rejected activation restores the prior plist and loaded state where known.
The installer keeps backups in the user's ccusage log directory. An inactive
existing plist needs its intent established before it can be replaced. For
a healthy manual restart, operate only on the named job and confirm that
the file was regenerated from the same inputs without duplicate totals.
